# 测试任务开发规范

## 必需内容

公开任务目录：

```text
TASK.md
task.toml
starter/
public-tests/
```

私有 evaluator 位于 `private/hidden-tests/<task-slug>/`，并由 `task.toml` 的 `private_scorer` 字段引用。

## 开发流程

1. 先写能力地图。每项评分要求必须有唯一归属和明确权重。
2. 编写正确的私有参考实现。
3. 编写确定性的公开 smoke tests，只公开接口而不泄露所有边界案例。
4. 编写覆盖边界、异常、不变量、重启和回归的隐藏测试。
5. 使用 untouched starter、参考实现以及至少两个故意不完整的 mutation 校准 scorer。
6. 冻结哈希并设置版本；评分语义改变必须提升任务版本。

## 质量要求

- 不联网也必须能够完成任务。
- 公开题面必须声明全部必需行为。隐藏测试可以隐藏示例，不能隐藏需求。
- 修改测试、删除 fixture、伪造证据或针对隐藏输入硬编码都不能获得分数。
- 优先测试行为与不变量，不依赖具体代码结构。
- 只有无法确定性评测的能力才考虑 LLM Judge，并尽量不让它决定 ShipReady。
- 任务优化质量和运行效率必须分开记录。

## 优化任务

每个实例必须具有确定性 baseline，以及冻结的 best-known 目标、正确 oracle 或有效下界。合法性始终是门槛；非法解不能获得优化质量分。实例应来自多个预先冻结的分布，避免一种启发式算法控制全部结果。
